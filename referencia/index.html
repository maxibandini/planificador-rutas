    Grafo¶

    Red de rutas: grafo no dirigido con pesos, en lista de adyacencia.

    Se usa lista y no matriz porque la red es dispersa: ocupa O(V + E) de memoria contra O(V^2), y recorrer los vecinos de un nodo, que es lo unico que piden Dijkstra y A*, es la operacion barata.

    Algoritmos de búsqueda¶

    Busqueda de rutas. V = nodos, E = tramos.

    ==================== ================ =================================== Algoritmo Complejidad Comentario ==================== ================ =================================== bfs O(V + E) minimiza tramos, no distancia dijkstra_lista O(V^2) V vueltas x V para hallar el minimo dijkstra_heap O((V+E) log V) el minimo sale del heap en O(log V) a_estrella O((V+E) log V) misma cota, explora mucho menos ==================== ================ ===================================

    En el primer parcial dijkstra_heap y a_estrella eran dos funciones casi identicas. Ahora comparten :func:_busqueda_con_heap: Dijkstra es A* con una heuristica que siempre vale cero.

    ALGORITMOS = {'BFS': bfs, 'Dijkstra lista': dijkstra_lista, 'Dijkstra heap': dijkstra_heap, 'A*': a_estrella} module-attribute ¶

    Algoritmos disponibles, por nombre para mostrar.

    Caché de rutas¶

    Reutilizacion de rutas ya calculadas.

    Memoizacion: guarda por argumentos y no se entera si cambia el mapa. Caching: guarda y ademas invalida las rutas que usaban el tramo cortado. La cache descarta por LRU. No tiene TTL: un corte de ruta es un evento, no algo que vence con el tiempo.

    CacheDeRutas ¶

    Cache de rutas con invalidacion selectiva por tramo y politica LRU.

    Ademas de las rutas guarda un indice invertido tramo -> rutas que lo usan. Cuando se corta un tramo, el indice dice exactamente que rutas borrar, sin recorrer toda la cache.

    No es segura para varios hilos: quien la comparta debe protegerla con un lock (ver :mod:planificador.api).

    Example

    from planificador.red import red_argentina cache = CacheDeRutas(red_argentina()) _ = cache.consultar("Ushuaia", "Salta") _ = cache.consultar("Ushuaia", "Salta") cache

    Archivos grandes¶

    Entrada y salida de archivos grandes de consultas.

    Una empresa de logistica recibe cada dia un archivo con millones de pedidos de ruta y tiene que devolver otro archivo con los resultados. Este modulo resuelve ese flujo como una tuberia de generadores::

    leer  ->  resolver  ->  escribir

    Cada etapa se puede cambiar por separado, y asi se mide el efecto de cada tecnica de E/S de la unidad 5:

    • Streaming: leer linea a linea con un generador en lugar de readlines(). La memoria queda acotada, no crece con el archivo.
    • Buffer: abrir el archivo una vez y dejar que el buffer agrupe las escrituras, en lugar de abrir y cerrar por cada linea.
    • Batching: procesar y escribir de a lotes (writelines), y en la base de datos insertar con executemany y un commit por lote.
    • Paralelismo: repartir los lotes entre procesos, con una ventana acotada de lotes en vuelo para no cargar todo el archivo en memoria.

    Formato de entrada: una consulta por linea, origen;destino. Formato de salida: origen;destino;costo;nodos_en_ruta.

    Concurrencia¶

    Resolver muchas consultas a la vez: secuencial, hilos y procesos.

    Las consultas son independientes y solo leen el mapa, asi que no hace falta lock. Es trabajo de CPU: por el GIL los hilos quedan cerca del tiempo secuencial, y los procesos aprovechan varios nucleos cuando el lote amortiza su costo fijo de arranque.

    NUCLEOS = min(8, os.cpu_count() or 4) module-attribute ¶

    Trabajadores por defecto.

    Ocho alcanzan para mostrar el paralelismo sin crear decenas de procesos en equipos grandes, y coinciden con la corrida del primer parcial.

    API web¶

    API web del planificador, hecha con Flask.

    Flask es un micro-framework: trae ruteo, plantillas y un cliente de pruebas, y deja elegir el resto. Alcanza para exponer el planificador como servicio HTTP sin la estructura de un framework completo como Django.

    Rutas

    GET / pagina con formulario y mapa. GET /api/ciudades ciudades disponibles. GET /api/ruta ruta entre origen y destino. GET /api/comparar la misma consulta con los 4 algoritmos. POST /api/tramos/cortar corta un tramo e invalida la cache. POST /api/reiniciar vuelve al mapa original. GET /api/cache estadisticas de la cache.

    ConsultaInvalidaError ¶

    Bases: ValueError

    Error en los datos de una peticion. Se responde con HTTP 400.

    ServicioDeRutas ¶

    Capa de servicio: mapa y cache compartidos por todas las peticiones.

    El servidor atiende cada peticion en un hilo distinto, y la cache modifica un OrderedDict en cada consulta. Sin el lock dos hilos podrian corromperla. El lock serializa los calculos, pero con el GIL el trabajo de CPU en hilos tampoco correria en paralelo.

    red Red | None

    Mapa de ciudades (nodos con nombre). Por defecto, las ciudades argentinas.
